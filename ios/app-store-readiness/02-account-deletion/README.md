# 앱 내 계정 삭제

- 작성일: 2026-08-12
- 우선순위: 제출 전 필수
- 상태: 미구현
- 관련 심사 항목: App Review Guideline 5.1.1(v)

## 목표

계정을 만들 수 있는 사용자가 앱 안에서 계정 삭제를 시작하고 완료할 수 있게 한다.
현재 iOS 설정의 회원 탈퇴 동작은 실제 삭제가 아니라 관리자 문의 안내에 머물러 있으므로 심사 거절 가능성이 높다.
단순 로그아웃, 계정 비활성화, 고객센터 문의만으로 완료 처리하지 않는다.

## 현재 확인된 위치

- iOS 탈퇴 UI: [SettingsView.swift](../../Dutypark/Features/Settings/SettingsView.swift)
- iOS 인증 상태: [SessionStore.swift](../../Dutypark/Core/Auth/SessionStore.swift)
- iOS API 클라이언트: [APIClient.swift](../../Dutypark/Core/Networking/APIClient.swift)
- 웹 공통 인증 클라이언트: [client.ts](../../../frontend/src/api/client.ts)
- 백엔드 인증 필터: [JwtAuthFilter.kt](../../../src/main/kotlin/com/tistory/shanepark/dutypark/security/filters/JwtAuthFilter.kt)
- 백엔드 쿠키 처리: [CookieService.kt](../../../src/main/kotlin/com/tistory/shanepark/dutypark/security/service/CookieService.kt)

경로가 리팩터링되면 실제 클래스명을 `rg --files`로 다시 찾아 이 문서 링크도 갱신한다.

## 먼저 결정할 정책

- [ ] 삭제가 즉시 완료되는지, 7~30일 복구 유예 후 완료되는지 결정한다.
- [ ] 유예 기간 중 로그인하면 삭제 요청을 취소할 수 있는지 결정한다.
- [ ] 법적 보존 의무가 있는 데이터와 보존 기간을 개인정보 처리방침에 적는다.
- [ ] 삭제 데이터, 익명화 데이터, 유지 데이터의 목록과 근거를 만든다.
- [ ] 삭제 요청 뒤 사용자에게 보일 상태와 예상 완료 시점을 정한다.
- [ ] 재가입 시 같은 소셜 식별자를 새 계정으로 허용할지 정한다.

## 도메인별 처리 규칙

### 팀과 권한

- [ ] 사용자가 팀장 또는 유일한 관리자인 팀을 조회한다.
- [ ] 권한 이관 없이 탈퇴할 수 없게 할지, 팀을 해산할지 정책을 정한다.
- [ ] 이관 방식이라면 후보 관리자 선택과 재확인 단계를 제공한다.
- [ ] 팀원이 없는 개인 팀도 같은 규칙으로 처리한다.
- [ ] 탈퇴 직전 권한이 바뀌는 경쟁 조건을 트랜잭션 안에서 다시 검증한다.

### 관계와 공유 데이터

- [ ] 친구, 가족, 팀원, 관리자-보조 계정 관계를 모두 해제한다.
- [ ] 보낸 요청과 받은 요청, 초대, 대기 상태 레코드를 정리한다.
- [ ] 사용자가 만든 공개 일정과 공유 일정의 소유권 또는 삭제 규칙을 정한다.
- [ ] 공동 Todo와 댓글성 사용자 콘텐츠가 있다면 소유자 표시 방식을 정한다.
- [ ] 다른 사용자 화면에서 탈퇴 사용자의 이름과 프로필이 노출되지 않게 한다.
- [ ] 감사 이력 보존이 필요하면 사용자 식별자를 비가역 익명값으로 치환한다.

### 첨부파일

- [ ] `SCHEDULE`, `PROFILE`, `TEAM`, `TODO` 컨텍스트별 소유 파일을 조회한다.
- [ ] 공유 객체가 유지되는 경우 첨부파일도 유지할지 소유권을 이관할지 결정한다.
- [ ] DB 레코드와 실제 스토리지 파일을 함께 삭제하는 재시도 가능한 작업을 만든다.
- [ ] 삭제 실패가 조용히 누락되지 않도록 운영 로그와 재처리 경로를 둔다.

### 인증과 외부 연동

- [ ] 모든 access/refresh 세션을 서버에서 즉시 무효화한다.
- [ ] 현재 기기뿐 아니라 사용자의 모든 APNs device token을 제거한다.
- [ ] 웹 푸시 subscription과 앱 배지/읽지 않음 상태도 정리한다.
- [ ] Apple 계정으로 가입했다면 Apple refresh token 또는 authorization code 기반 revoke를 수행한다.
- [ ] Kakao와 Naver는 연결 해제와 서비스 회원 탈퇴의 차이를 확인해 정책대로 호출한다.
- [ ] 외부 revoke가 일시 실패해도 계정 삭제 요청은 기록하고 재시도한다.
- [ ] 외부 제공자 토큰과 응답 전문은 로그에 남기지 않는다.

### 보조 계정과 impersonation

- [ ] 주 계정이 만든 보조 계정을 함께 삭제할지 독립 계정으로 전환할지 결정한다.
- [ ] 보조 계정이 주 계정 삭제를 요청할 수 있는지 권한 규칙을 정한다.
- [ ] 관리자가 사용자를 impersonation 중일 때 탈퇴 요청을 명시적으로 거부한다.
- [ ] impersonation 세션에서 거부되는 이유를 기계 판독 가능한 오류 코드로 반환한다.
- [ ] 실제 사용자 세션으로 돌아온 뒤에만 삭제 확인 화면에 접근하게 한다.

## 백엔드 구현 체크리스트

- [ ] 본인 인증이 필요한 계정 삭제 요청 API를 추가한다.
- [ ] 최근 로그인 확인 또는 비밀번호/소셜 재인증 단계를 둔다.
- [ ] 삭제 전 영향 범위를 조회하는 사전 점검 API를 제공한다.
- [ ] 팀장·유일 관리자 문제를 구체적인 오류 코드와 해결 방법으로 반환한다.
- [ ] 삭제 서비스는 트랜잭션 경계를 명확히 하고 멱등하게 만든다.
- [ ] DB 삭제, 익명화, 외부 revoke, 파일 삭제의 순서와 보상 동작을 문서화한다.
- [ ] 삭제 완료 전에 refresh token과 device token을 다시 발급하지 못하게 한다.
- [ ] API 응답과 서버 로그에서 개인정보 및 소셜 토큰을 마스킹한다.
- [ ] 삭제 처리 감사 로그에는 필요한 최소 정보만 제한 기간 동안 보존한다.

## iOS 구현 체크리스트

- [ ] 설정 화면에 실제 `계정 삭제` 진입점을 제공한다.
- [ ] 삭제되는 데이터와 유지될 수 있는 데이터를 짧고 명확하게 설명한다.
- [ ] 팀 권한 이관이 필요하면 해당 화면으로 이동할 수 있게 한다.
- [ ] 오입력 방지를 위해 최종 확인과 재인증을 요구한다.
- [ ] 삭제 요청 성공 후 쿠키, 인증 상태, 캐시, 사용자별 로컬 데이터를 지운다.
- [ ] APNs 등록을 해제하고 이전 계정 토큰이 다음 계정에 연결되지 않게 한다.
- [ ] 네트워크 실패를 성공처럼 보이지 말고 재시도 가능한 상태로 표시한다.
- [ ] VoiceOver, Dynamic Type, 44pt 터치 영역을 확인한다.

## 웹 구현 체크리스트

- [ ] 웹 설정에도 동일한 계정 삭제 기능과 정책 설명을 제공한다.
- [ ] iOS와 동일한 사전 점검 및 재인증 API를 사용한다.
- [ ] 성공 시 서버 세션, 웹 푸시 subscription, Pinia 상태와 사용자 캐시를 정리한다.
- [ ] 모든 사용자 문구를 `ko`, `en`, `ja`, `zh`, `es` 번역에 추가한다.
- [ ] 모바일·데스크톱, 라이트·다크 모드에서 확인한다.

## 테스트

- [ ] 일반 사용자가 삭제 후 어떤 보호 API에도 접근하지 못한다.
- [ ] 같은 삭제 요청을 반복해도 500 오류나 데이터 손상이 없다.
- [ ] 유일 팀장, 복수 관리자, 팀원, 팀 없는 사용자 경우를 각각 검증한다.
- [ ] 친구·가족·초대·보조 계정 관계가 남지 않는지 검증한다.
- [ ] 공개·공유 일정, Todo, 첨부파일의 정책이 그대로 적용되는지 검증한다.
- [ ] 모든 refresh session, APNs token, 웹 푸시 구독이 제거되는지 검증한다.
- [ ] Apple, Kakao, Naver revoke 성공·실패·재시도를 검증한다.
- [ ] impersonation 세션의 요청이 거부되는지 검증한다.
- [ ] 삭제 중 서버 오류와 네트워크 단절 뒤 재요청을 검증한다.
- [ ] TestFlight 실기기에서 삭제 진입부터 완료까지 끝까지 실행한다.

## 완료 조건

- [ ] 사용자가 외부 문의 없이 iOS 앱 안에서 삭제를 시작하고 완료할 수 있다.
- [ ] 유일 관리자 등 즉시 삭제할 수 없는 이유와 사용자의 다음 행동이 화면에 표시된다.
- [ ] 계정 삭제 정책과 실제 데이터 처리 결과가 개인정보 처리방침과 일치한다.
- [ ] 서버·iOS·웹 자동 테스트 및 실기기 회귀 테스트가 통과한다.
- [ ] App Review Notes에 삭제 메뉴 경로와 필요한 심사 계정 정보를 적는다.
- [ ] 운영 환경에서 삭제 작업 실패를 탐지하고 안전하게 재처리할 수 있다.
