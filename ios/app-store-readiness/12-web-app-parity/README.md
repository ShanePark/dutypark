# 12. 웹 → iOS 기능·UX 동등성

- 기준일: 2026-08-14
- 상태: 대부분의 화면과 API 연동은 구현됐으나, 실제 미구현·계약 결정·웹 교차 검증이 남아 있음
- 목표: 일반 사용자용 웹 기능과 출시 앱에 유지하는 서비스 관리자 기능을 iOS에서 같은 권한·데이터·결과로 제공

SwiftUI 화면이나 targeted test가 존재한다는 사실만으로 이식 완료로 보지 않는다.
각 항목은 실제 서버 쓰기·재조회, 권한별 계정과 같은 데이터의 웹 확인까지 통과해야 완료다.

## 1. 실제 미구현 기능

- [ ] **일정 수동 정렬:** 서버 `PATCH /api/schedules/positions`를 호출하는 iOS repository와 UI를 구현한다.
- [ ] 같은 날짜 안에서 순서를 바꾼 뒤 앱 재조회와 웹 접속에서도 순서가 유지되는지 검증한다.

일정 삭제는 구현돼 있으므로 수동 정렬과 함께 완료된 것으로 기록하지 않는다. 현재 확인된 일반 사용자 기능 중 명백한 endpoint/UI 부재는 이 항목이며, 아래 나머지는 계약·범위·검증 gap이다.

## 2. API·권한 계약 gap

앱에서 임의로 우회하거나 웹보다 권한을 확대하지 않는다. 공통 서버 계약을 바꿔야 하면 웹 영향과 회귀 계획을 먼저 확정한다.

| 대상 | 현재 gap | 완료 조건 |
| --- | --- | --- |
| AI 정책 공개 조회 | iOS guest API는 `ai-schedule-parsing`을 요청하지만 서버 `PolicyType`은 `AI_SCHEDULE_PARSING`을 사용해 현재 경로가 `400`이 될 수 있다. | 앱과 서버가 같은 정책 식별자를 사용하도록 고치고 로그인 전 한국어·영어 정책 조회를 계약 테스트로 고정한다. |
| 일정 검색 DTO | 웹이 기대하는 `id`, `description`, `hasAttachments` 등과 서버 검색 응답이 일치하지 않을 수 있다. | 실제 응답 fixture로 계약을 고정하고 검색·페이지 이동·달력 강조를 앱과 웹에서 검증한다. |
| 팀 관리 권한 | 웹 노출 조건과 서버의 팀 매니저·대표 관리자 허용 범위가 일부 다를 수 있다. | 대표 관리자·팀 매니저·일반 멤버별 허용/거절을 재현하고 앱 UI를 확정된 서버 계약에 맞춘다. |
| 근무·개인 관리자 권한 | 서버 쓰기 권한이 웹의 본인/개인 위임 manager 범위보다 넓고, 웹은 manager 후보를 가족으로 제한한다. | 앱은 현재 웹 범위를 유지하며 본인·가족 manager·권한 없는 계정으로 교차 검증한다. |
| 첨부 편집 | `orderedAttachmentIds` 누락 시 기존 첨부가 모두 삭제될 수 있다. | 일정·Todo 편집에서 기존 ID를 항상 보내고 추가·제거·정렬 후 앱·웹 재조회로 데이터 보존을 확인한다. |
| 첨부 용량 | 앱 제한은 10MB, 웹·백엔드 표시는 50MB이며 운영 proxy 한도가 확정되지 않았다. | 실제 운영 업로드 한도를 측정해 하나의 사용자 정책으로 정하고 앱·웹·서버 설정과 문구를 일치시킨다. |
| 프로필 사진 공개범위 | 프로필 본문은 공개범위를 적용하지만 사진 조회는 member ID만으로 익명 접근과 장기 public cache가 가능하다. | PRIVATE 회원 사진을 공개할 제품 정책인지 결정하고, 의도하지 않았다면 서버 권한·캐시와 앱·웹 표시를 함께 수정한다. |
| 날짜·시간 | 일정은 timezone 없는 `LocalDateTime` 계약을 사용한다. | 한국 시간대와 다른 기기 시간대에서 저장·조회·검색·다일 일정의 달력 날짜가 웹과 같음을 실제 서버에서 검증한다. |
| 오류 현지화 | 운영 API의 오류 `code`별 사용자 문구가 한국어·영어에서 완전히 고정되지 않았다. | 주요 `400/401/403/404/409/429/5xx` code를 fixture와 실제 서버로 재현하고 원문·개발자 메시지 대신 행동 가능한 현지화 문구를 표시한다. |

## 3. WebView와 SSO UX parity

- [ ] 가이드·릴리스 노트와 관리자 개발/API 문서의 `WKWebView`를 네이티브 원칙의 허용 예외로 둘지 결정한다.
- [ ] WebView를 유지하면 로그인 cookie, 내부·외부 링크, 뒤로가기, 로딩, 오프라인·인증 만료·서버 오류 복구를 검증한다.
- [ ] 네이티브로 바꾸면 웹 콘텐츠의 한국어·영어, 갱신 방식과 링크 동작을 빠뜨리지 않는다.
- [ ] 웹의 SSO 가입 완료 화면과 달리 iOS가 가입 직후 로그인되는 차이를 유지할지, 완료 안내 화면을 이식할지 결정한다.
- [ ] Kakao·Naver 신규 가입에서 성공·취소·오류·중복 연결 후 목적지와 성공 피드백을 웹과 교차 검증한다.

## 4. 시각·정보 구조 동등성

- [ ] 로그인·SSO, 홈, 캘린더·일정·근무, Todo, 친구·가족, 팀·팀 관리, 알림, 첨부, 프로필·설정·정책·공개 화면을 현재 모바일 웹과 화면별로 대조한다.
- [ ] 정보 우선순위, 빈 상태, loading, validation, 오류, 권한 없음과 destructive confirm이 웹과 의미상 일치한다.
- [ ] 웹의 디자인 token·간격·타이포그래피·색상·카드·modal·상태 표현을 네이티브 조작 관례 안에서 일치시킨다.
- [ ] 작은 화면 `375×812`과 큰 화면 `402×874`, 한국어·영어, Light·Dark에서 증거를 남긴다.
- [ ] Dynamic Type, VoiceOver와 44pt 검증은 [09. 품질·접근성](../09-quality-accessibility/README.md)의 완료 조건을 함께 충족한다.

## 5. 명시적 제외 범위

다음은 웹 → 앱 동등성 완료 조건에 포함하지 않는다.

- 오프라인 읽기 캐시, 오프라인 쓰기와 충돌 해결
- PWA 설치 안내, Service Worker와 브라우저 VAPID 구독 UI
- 현재 웹 UI가 사용하지 않는 `TEAM`·`PROFILE` 일반 첨부 화면. 프로필 사진은 전용 API로 제공한다.
- 서버에만 있는 legacy Todo 목록·calendar/due/overdue/position endpoint와 `DELETE /api/duty/override`
- 별도 공개 share token. 기존 공개 HTTPS 캘린더 링크와 Universal Link를 사용한다.
- iPad 적응형 UI와 가로 방향

Kakao·Naver·Apple 연결 해제, system theme, 계정 삭제, 일정·Todo 첨부, 팀 대표·매니저용 팀 관리는 현행 웹 기능이므로 제외하지 않는다.

## 6. 실서버·웹 교차 완료 기준

- [ ] 운영 유사 서버와 실제 iPhone에서 신규 가입·세션 복원/만료·로그아웃을 공급자별로 검증한다.
- [ ] 일정·근무·D-Day·Todo·첨부·친구·가족·팀·알림·프로필을 생성·수정·삭제하고 앱 재조회와 웹 접속에서 같은 결과를 확인한다.
- [ ] 소유자, 태그 사용자, 친구, 가족, 개인 manager, 팀 대표·manager·일반 멤버와 비회원 권한을 각각 검증한다.
- [ ] 서비스 관리자 계정으로 회원·세션·팀 관리와 destructive confirm을 검증하고, 비관리자 계정에서는 관리자 메뉴·API·WebView 접근이 차단되는지 확인한다.
- [ ] Kakao/Naver/Apple 로그인·가입·연결·해제, APNs와 Universal Link는 각 상세 출시 문서의 E2E 조건도 충족한다.
- [ ] 앱 변경이 기존 웹 OAuth, 쿠키 세션, Web Push, API DTO와 오류 code를 깨뜨리지 않는 회귀 테스트를 통과한다.
- [ ] 일정 수동 정렬과 모든 계약·UX 결정을 닫고, 차단 결함·미승인 차이가 없는 동일 빌드로 시각 QA까지 완료한다.

위 조건을 모두 충족하기 전에는 “웹 기능 이식 완료”로 표시하지 않는다.
