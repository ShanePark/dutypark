# 10. 사용자 생성 콘텐츠(UGC) 안전장치

- 기준일: 2026-08-14
- 상태: 정책·신고·차단·운영 처리 구현 필요
- 심사 기준: [App Review Guidelines 1.2 — User-Generated Content](https://developer.apple.com/app-store/review/guidelines/#user-generated-content)

Dutypark는 일정, Todo, 프로필 사진과 첨부파일을 친구·가족·팀 구성원에게 공유하고 공개 캘린더로 노출할 수 있다.
따라서 지인 중심 서비스여도 다른 사용자의 콘텐츠를 보는 모든 경로에 신고·차단·운영 조치를 일관되게 적용한다.

## 1. 신고

- [ ] 일정, Todo, 프로필 사진, 첨부파일과 공개 캘린더의 노출 지점에서 앱 안의 `신고` 동작을 제공한다.
- [ ] 신고 사유, 선택 설명, 대상·신고자·접수 시각과 감사 가능한 콘텐츠 참조를 서버에 저장한다.
- [ ] 중복 제출을 방지하고 접수 결과와 예상 처리 시간을 한국어·영어로 안내한다.
- [ ] 신고자의 신원과 신고 내용은 대상 사용자에게 노출하지 않고 최소 권한으로 보호한다.

## 2. 사용자 차단

- [ ] 친구 삭제와 별개의 사용자 차단·차단 목록·해제 기능을 앱과 서버에 구현한다.
- [ ] 차단 즉시 일정·Todo·프로필·첨부, 검색, 친구 요청·초대·공유와 신규 알림을 숨기거나 차단한다.
- [ ] 기존 친구·공유 관계, 같은 팀 콘텐츠와 차단 해제 시 복원 범위를 제품 정책으로 확정한다.
- [ ] 공개 링크처럼 로그인하지 않고 열리는 콘텐츠는 사용자 차단과 별도로 운영자가 게시 중단할 수 있다.

## 3. 운영자 moderation

- [ ] 운영자가 신고 목록, 대상 콘텐츠, 증거와 처리 이력을 조회할 최소 권한 관리 화면 또는 도구를 제공한다.
- [ ] 콘텐츠 숨김·삭제, 계정 제한·정지, 신고 기각과 신고자 통지를 기록한다.
- [ ] 조치한 콘텐츠가 앱, 검색, 공개 링크, 알림, 캐시와 첨부 저장소에서 함께 제거되는지 검증한다.
- [ ] 금지 콘텐츠, 반복 위반, 증거 보존, 제재 단계와 이의제기를 포함한 이용 정책을 로그인 없이 공개한다.
- [ ] 일반 사용자는 다른 사용자의 신고, 운영 메모와 내부 조치 기록을 조회할 수 없다.

## 4. 운영 연락처와 SLA

- [ ] App Store의 Support URL과 앱 설정에 실제 응답 가능한 이메일 또는 문의 양식을 게시한다.
- [ ] 신고 접수·판단·조치·통지·이의제기 절차와 담당자·대체 담당자를 정한다.
- [ ] 긴급 안전·불법 콘텐츠, 괴롭힘·혐오, 일반 스팸과 이의제기별 현실적인 1차 응답 SLA를 확정해 공개 정책과 내부 절차에 반영한다.
- [ ] 법적 긴급 요청, 증거 보존과 관계기관 신고가 필요한 경우의 내부 에스컬레이션 경로를 정한다.

## 5. E2E 검증

- [ ] 사용자 A의 공유 일정·첨부를 사용자 B가 신고하고 운영자가 조회·조치한 뒤 앱·웹·공개 링크에서 제거됨을 확인한다.
- [ ] B가 A를 차단하면 양방향 공유·검색·친구 요청·초대·알림이 중단되고 예약된 알림과 badge도 정리된다.
- [ ] 팀원 차단, 팀 탈퇴, 친구 삭제, 차단 해제와 계정 삭제가 정책대로 동작한다.
- [ ] 오프라인 재시도에도 신고가 중복 저장되지 않는다.
- [ ] 한국어·영어, VoiceOver와 작은 화면에서 신고·차단·취소·확인을 완료한다.
- [ ] 심사 계정 두 개로 신고, 차단과 운영 조치 위치를 재현할 수 있게 Review Notes에 경로를 적는다.

## 완료 조건

- [ ] 신고, 차단, moderation, 연락처와 SLA가 운영 환경에서 실제 동작한다.
- [ ] 콘텐츠·첨부·검색·알림·공개 링크를 통한 우회가 E2E에서 발견되지 않는다.
- [ ] 이용 정책·Support URL을 로그인 없이 열 수 있고 심사 계정으로 전체 흐름을 재현할 수 있다.
